## 一、数据来源

- 招投标公告数据来源于中国政府采购网（ccgp）与全国公共资源交易平台（ggzy_national）等官方公开平台，均为公开发布信息。
- 产品实际采集能力：2 个官方来源适配器（v4.1 §5.1 已冻结范围：ccgp + ggzy_national）。
- 采集行为遵守目标站点 robots.txt 协议（v4.1 §5.3 robots_checker.py，30 分钟域名级缓存，不可达时默认允许），域名级频率限制为 <= 1 次 / 8 秒（v4.1 §5.3 rate_limiter.py，按域名独立计数）。
- 遇 HTTP 403 立即停止抓取，不切换 UA、不更换代理重试；失败时回滚频率限制 reservation（DomainRateLimiter.release()）。
- robots-法律说明：v4.1 §5.3 设计为「robots.txt 不可达时默认允许」，基于以下依据：(1) ccgp 与 ggzy_national 属于政府信息公开渠道，依据《政府信息公开条例》具有公共利益属性；(2) 《数据安全法》未禁止公开数据的自动化聚合；(3) 技术实现已包含 30 分钟域名级缓存与失败计数，避免因网络抖动导致的合规风险。严格司法管辖区可改为「默认拒绝」，当前选择已在风险登记册中记录。
- 公告内容版权归原作者 / 发布机构所有，本系统仅做信息聚合与字段抽取，不主张版权。
- 不绕过登录墙、不抓取付费内容、不存储原始 HTML 全文（仅保存抽取后的结构化字段）。
- 来源白名单（v4.1 §5.3 source_whitelist.py）：维护允许采集的来源平台/域名清单，支持域名归一化、子域匹配、运行时下架/重新启用，集成到 scraper 前置检查。
- 数据删除（v4.1 §5.3 data_deletion.py）：支持按来源 URL、来源平台、公告来源实例、页面快照、用户授权数据 5 种范围删除，记录审计日志。

## 二、隐私保护

- 联系人电话 contact_phone / 邮箱 contact_email 使用 SHA256 hex 存储，不入库存明文。
- API key 使用 HMAC-SHA256 摘要（v4.1 §13.1，基于服务端密钥），服务端只保存摘要，比对使用 secrets.compare_digest 防止时序攻击。
- 密码使用 Argon2id 哈希（v4.1 §13.1 credentials.py，防彩虹表/暴力破解）。
- Cookie 使用 AES-GCM 加密（v4.1 §13.1 credentials.py，nonce 唯一）。
- 系统不收集用户个人身份信息（PII），不建立用户画像。
- 附件文件名做路径遍历净化：去除 ../ 与 Windows 非法字符，最终路径再校验是否落在 ATTACHMENT_DIR 之内。
- 所有外部 URL 请求前校验目标 IP，拒绝私有 / 回环 / 链路本地 / 云元数据地址，防止 SSRF；重定向后重新检查。
- 日志输出对电话 / 邮箱 / key 字段做脱敏处理，不打印明文；日志不得记录凭证。
- 数据库连接串、第三方密钥等敏感配置通过环境变量注入，不入库不入仓。
- 加密密钥通过环境密钥或密钥管理服务提供，nonce 必须唯一。

## 三、AI 反幻觉（风险提示）

- 报告输出明确标注「AI 生成，仅供参考，决策请人工复核」字样。
- 本系统定位为数据服务商，不提供金融建议，不承担金融决策责任。
- 证据验证流水线（v4.1 §6）：LLM 只生成字段和证据候选，确定性程序在原文快照中搜索验证，找不到依据的字段一律标记为无依据不输出。
- 5 级降级匹配引擎（v4.1 §6.3）：精确匹配 / 空白归一化 / 全半角统一 / 金额日期格式变体 / 模糊匹配，逐级降级寻找证据。
- 双坐标证据映射（v4.1 §4.10）：建立 normalized_character_index to clean_raw_text_character_index 映射，前端在清洗后原始文本快照中高亮证据，不依赖实时网页 DOM。

## 五、行业边界

- 本系统是面向供应链金融贷前尽调的可验证招投标数据引擎，不是投资顾问，不是信用评级机构。
- 不提供投标决策建议，不承诺中标结果。
- 不输出供应商信用评分（v4.1 §9.1）。供应商公开活动观察度基于公开中标数据生成，仅反映系统覆盖范围内的公开招投标活动观察信号，不构成授信或投资依据。
- 不实施全品类 BOQ 异常检测（v4.1 §2.3 暂不实施项）。
- 不判断围标（v4.1 §2.3 暂不实施项）；高频共现提示仅作观察信号，附带说明「仅凭共现不能判断企业关联关系或围标行为」。
- 用户应自行核实信息准确性，决策风险自负。
- 系统输出不构成任何形式的要约或承诺，不作为合同或法律依据。

## 八、v4.1 关键要求补全

### 8.1 凭证安全（v4.1 第 13.1 节）

按 v4.1 总规划第 13.1 节要求，凭证安全执行以下规范（已全部实现）：

- API Key 使用高熵随机值，服务端只保存基于服务端密钥的 HMAC-SHA256 摘要（credentials.py 已实现）
- 密码使用 Argon2id（credentials.py 已实现，含 Argon2Error fallback）
- Cookie 使用 AES-GCM（credentials.py 已实现，nonce 唯一）
- 加密密钥通过环境密钥或密钥管理服务提供，nonce 必须唯一
- 日志不得记录凭证
- SSRF 防护（url_safety.py）：仅允许 HTTP/HTTPS，检查 IP 字面量，校验 DNS 解析结果，拦截内网/回环/链路本地/云元数据地址，重定向后重新检查，限制端口、超时和响应体大小
- 路径安全：使用白名单存储目录，使用真实路径校验，禁止路径穿越，文件名与真实存储键分离
- 单元测试覆盖：tests/test_credentials.py 45 个测试用例，分支覆盖率 100%

### 8.2 6 个 MVP 观察信号（v4.1 第 9.2 节）

标小智不输出供应商信用评分（v4.1 第 9.1 节），所有信号只反映系统覆盖来源和时间范围内观察到的公开招投标活动，供人工尽调参考。MVP 信号如下：

### 8.3 严谨表述（v4.1 第 9.3 节）

为避免误导用户，前端展示与对外输出采用以下严谨表述：

- 使用「公开公告中观察到的投标出现次数」，不得使用「企业实际投标次数」
- 集中度使用「当前覆盖公开中标记录中的采购人集中度」，不得使用「企业客户集中度或营业收入集中度」
- 高频共现必须附带说明：高频共现可能由行业集中度、区域市场和项目准入条件等多种因素造成。仅凭共现不能判断企业关联关系或围标行为。

### 8.4 高频问题对照（v4.1 第 18.3 节）

和招投标搜索平台有什么不同？
招投标搜索平台主要解决信息覆盖和检索问题；标小智主要解决结构化字段是否有原文依据、来源是否明确以及数据是否可追踪的问题。

可信度是否只是人工规则？
系统不依赖单一主观分数。抽取支持度、来源质量和交叉验证状态分别保存，展示规则在校准集上确定，并使用独立测试集验证实际准确率和覆盖率。

证据会不会也是模型编的？
不会直接采信。LLM 只提供候选证据文本，最终证据必须由程序在指定公告版本快照中搜索并验证，找不到就标记为无证据。

为什么不作信用评分？
公开招投标数据不足以代表企业整体信用。标小智只输出有明确数据口径的公开活动观察信号，不构成授信或投资依据。

为什么很多公告没有独立交叉验证？
同一业务公告通常只有一个原始发布主体，其他页面可能只是转载。单一官方原始来源加直接原文证据可以构成高可信，独立来源验证属于额外增强项。

数据采集是否合规？
MVP 优先处理无需登录的官方公开数据，检查平台规则并控制访问频率（域名级 8 秒）。商业平台仅在服务条款、接口协议或其他授权依据允许时接入，不绕过验证码、付费墙或技术限制。
