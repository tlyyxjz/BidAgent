# 标小智合规声明

本文件用于说明标小智项目在数据来源、隐私保护、AI 反幻觉、行业边界四个方面的合规情况，配套 W2 评测报告与 PPT 同口径数据。所有指标均来自 `_w2_report` 目录下的评测产物，口径一致。

- 版本：v1.0
- 发布日期：2026-07-28
- 适用范围：标小智全部采集、抽取、报告生成与对外输出环节。

---

## 一、数据来源

- 招投标公告数据来源于中国政府采购网等官方公开平台，均为公开发布信息。
- 产品实际采集能力：**2 个已冻结官方适配器**（ccgp 中国政府采购网 + ggzy_national 全国公共资源交易平台），v4.1 §5.1 明确不承诺覆盖全国所有地方子平台。
- 采集频率由 Playwright 内置请求间隔控制，遇 HTTP 403 立即停止。robots.txt 解析与域名级频率限制为 v4.1 §5.3 规划能力，当前 MVP 尚未实现。
- 遇 HTTP 403 立即停止抓取，**不切换 UA、不更换代理重试**（issue #34 已修复并固化此行为）。
- 公告内容版权归原作者 / 发布机构所有，本系统仅做信息聚合与字段抽取，不主张版权。
- 不绕过登录墙、不抓取付费内容。页面快照（HTML）保存用于版本追踪和证据定位（v4.1 §4.7 NoticeVersion），商业平台全文不随开源仓库发布。

---

## 二、隐私保护

- 联系人电话 `contact_phone` / 邮箱 `contact_email` 使用 **SHA256 hex** 存储，不入库存明文。
- API key 使用 **HMAC-SHA256 摘要 + `hmac.compare_digest`** 常量时间比对，防止时序攻击（v4.1 §13.1）。
- 系统不收集用户个人身份信息（PII），不建立用户画像。
- 附件文件名做路径遍历净化（issue #13）：去除 `../` 与 Windows 非法字符，最终路径再校验是否落在 `ATTACHMENT_DIR` 之内。
- 所有外部 URL 请求前校验目标 IP，**拒绝私有 / 回环 / 链路本地地址**，防止 SSRF。
- 日志输出对电话 / 邮箱 / key 字段做脱敏处理，不打印明文。
- 数据库连接串、第三方密钥等敏感配置通过环境变量注入，不入库不入仓。

## 三、AI 反幻觉（风险提示）

- 报告输出明确标注「**AI 生成，仅供参考，决策请人工复核**」字样。
- 本系统定位为数据服务商，**不提供金融建议，不承担金融决策责任**。
- 证据验证流水线：无依据字段不展示，`unjustified_rate` 从 100% 降至 **1.94%**。
- 证据边界质量（22 篇金标，未匹配算 0 口径）：**IoU avg 0.5307**，P50 = 0.96 / P95 = 1.0。
- 字段精确率（C 组完整流水线）：`field_precision` **94.49%**，`evidence_precision` **100%**。
- 已知限制：`recall` **69.90%**（LLM 随机性 + budget 值未被系统检出），W3 将优化提示词补强。

## 五、行业边界

- 本系统是面向供应链金融贷前尽调的**可验证招投标数据引擎**，不是投资顾问，不是信用评级机构。
- 不提供投标决策建议，**不承诺中标结果**。
- **不输出供应商信用评分**。供应商公开活动观察度基于公开中标数据生成，仅反映系统覆盖范围内的公开招投标活动观察信号，不构成授信或投资依据。
- BOQ 报价异常检测为实验性能力，结果仅供研究参考，不作为采购决策依据。
- 用户应自行核实信息准确性，**决策风险自负**。
- 系统输出不构成任何形式的要约或承诺，不作为合同或法律依据。

## 八、v4.1 关键要求补全

> 本节按 v4.1 总规划补全 compliance.md 中缺失的关键要求段落。

### 8.1 凭证安全（v4.1 第 13.1 节）

按 v4.1 总规划第 13.1 节要求，凭证安全执行以下规范：

- **API Key** 使用高熵随机值，服务端只保存基于服务端密钥的 **HMAC 摘要**（当前实现使用 SHA256 hash + `secrets.compare_digest` 比对，后续按 v4.1 升级为 HMAC 摘要）
- **密码**使用 **Argon2id**
- **Cookie** 使用 **AES-GCM**
- 加密密钥通过环境密钥或密钥管理服务提供，nonce 必须唯一
- 日志不得记录凭证
- **SSRF 防护**：仅允许 HTTP/HTTPS，检查 IP 字面量，校验 DNS 解析结果，拦截内网/回环/链路本地/云元数据地址，重定向后重新检查，限制端口、超时和响应体大小
- **路径安全**：使用白名单存储目录，使用真实路径校验，禁止路径穿越，文件名与真实存储键分离

### 8.2 6 个 MVP 观察信号（v4.1 第 9.2 节）

标小智不输出供应商信用评分（v4.1 第 9.1 节），所有信号只反映系统覆盖来源和时间范围内观察到的公开招投标活动，供人工尽调参考。MVP 信号如下：

| 信号 | 说明 |
|---|---|
| 中标活跃度 | 近 90 天公开中标次数和金额趋势，不作正负定性 |
| 公开中标集中度 | 当前覆盖数据中 Top 3 采购人及地区占比 |
| 废标公告关联 | 企业在废标或流标公告中被观察到的次数，不直接归因 |
| 明确投标否决 | 公告明确写明企业投标被否决，并记录原因 |
| 信息冲突观察 | 相同事实断言在不同有效来源中出现矛盾 |
| 高频共现提示（选做） | 企业与其他企业在同一标段被反复观察到，不用于判断围标 |

### 8.3 严谨表述（v4.1 第 9.3 节）

为避免误导用户，前端展示与对外输出采用以下严谨表述：

- 使用「**公开公告中观察到的投标出现次数**」，不得使用「企业实际投标次数」
- 集中度使用「**当前覆盖公开中标记录中的采购人集中度**」，不得使用「企业客户集中度或营业收入集中度」
- 高频共现必须附带说明：**高频共现可能由行业集中度、区域市场和项目准入条件等多种因素造成。仅凭共现不能判断企业关联关系或围标行为。**

### 8.4 高频问题对照（v4.1 第 18.3 节）

**和招投标搜索平台有什么不同？**
招投标搜索平台主要解决信息覆盖和检索问题；标小智主要解决结构化字段是否有原文依据、来源是否明确以及数据是否可追踪的问题。

**可信度是否只是人工规则？**
系统不依赖单一主观分数。抽取支持度、来源质量和交叉验证状态分别保存，展示规则在校准集上确定，并使用独立测试集验证实际准确率和覆盖率。

**证据会不会也是模型编的？**
不会直接采信。LLM 只提供候选证据文本，最终证据必须由程序在指定公告版本快照中搜索并验证，找不到就标记为无证据。

**为什么不作信用评分？**
公开招投标数据不足以代表企业整体信用。标小智只输出有明确数据口径的公开活动观察信号，不构成授信或投资依据。

**为什么很多公告没有独立交叉验证？**
同一业务公告通常只有一个原始发布主体，其他页面可能只是转载。单一官方原始来源加直接原文证据可以构成高可信，独立来源验证属于额外增强项。

**数据采集是否合规？**
MVP 优先处理无需登录的官方公开数据，检查平台规则并控制访问频率。商业平台仅在服务条款、接口协议或其他授权依据允许时接入，不绕过验证码、付费墙或技术限制。
