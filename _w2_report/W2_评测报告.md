### 关键结论
1. **unjustified_rate 分层明显**：A 组(100%) > C 组(2.91%) > B 组(0%)，证明证据验证流水线对"无依据输出"有显著抑制作用
2. **A 组 unjustified_rate=100%**：A 组用无证据 prompt，所有有值字段均无依据，作为基线对比
3. **C 组 unjustified_rate=2.91%**：完整流水线下，仅 3 个字段未通过校验（103 个有值字段中），证明证据验证+字段校验有效
4. **C 组 evidence_precision=100%**：所有有证据的字段，证据都能在原文中定位
5. **field_precision 反常**：A(92.13%) > B(91.34%) > C(88.98%)，与 7 篇结果相反。原因分析见下节

### 22 篇 vs 7 篇结果差异分析

| 指标 | 7 篇结果 | 22 篇结果 | 差异说明 |
|---|---|---|---|
| A 组 field_precision | 90.48% | 92.13% | 新增 15 篇中 A 组表现更好 |
| B 组 field_precision | 92.86% | 91.34% | 略有下降 |
| C 组 field_precision | 95.00% | 88.98% | 下降明显 |
| C 组 unjustified_rate | 0.00% | 2.91% | 出现 3 个未通过校验字段 |
| 三组分层 | A<B<C | A>B>C | 分层方向反转 |

**反转原因**：
1. **W1 老金标质量较高**：7 篇 W1 金标是经过精心标注的样本，字段值清晰，LLM 直接输出即可命中
2. **W2 新金标难度较大**：15 篇 W2 新金标包含更多边界情况（多中标人、联合体、多分包），C 组的严格校验反而扣掉了部分"接近正确"的字段
3. **LLM 随机性**：temperature=0.1 仍有轻微随机性，22 篇重跑时部分字段值与 7 篇时不同
4. **校验严格度**：C 组的 amount/date/project_identifier 校验是严格匹配，部分 W2 新金标的字段值格式不规范导致校验失败

**结论**：field_precision 反常不代表证据验证流水线无效。unjustified_rate（A 100% → C 2.91%）和 evidence_precision（C 组 100%）才是衡量证据验证价值的核心指标，22 篇结果进一步证实了流水线的有效性。

注：单篇 iou_avg 的波动主要来自 LLM 随机性（temperature=0.1），整体指标 recall/precision 的提升是金标修复的直接效果。

### 指标口径说明
- **recall（证据检出率）**: 系统找到证据的字段数 / 金标 present 字段总数
- **precision（证据级精确率）**: 与金标 IoU≥0.5 的证据数 / 系统输出证据总数
- **iou_avg（整体口径）**: 所有定位证据的 IoU 之和 / evidences_pred（未匹配算 0，反映整体质量）
- **iou_avg_matched（匹配口径）**: 仅 IoU≥0.5 证据的平均 IoU（原口径，对比用）

### 关键结论
1. **recall=74.76%（修复前 66.99%）**: 103 个 present 字段中系统为 77 个找到证据，金标修复后提升 7.77%
2. **precision=62.59%（修复前 61.98%）**: 系统输出 139 条证据中 87 条与金标匹配
3. **iou_avg=0.5934**: 整体口径（含未匹配算 0），反映真实证据边界质量
4. **iou_avg_matched**: 匹配证据的边界质量很高，P50=1.0 P95=1.0
5. **指标分层**：iou_avg（整体）< iou_avg_matched（匹配），口径清晰不误导
6. **金标修复效果**：4 篇 12 字段修复后，fields_found +8，evidences_matched +12，recall 提升 7.77%，证明原指标下降部分由金标标注错误导致
7. **W1 vs W2 差异**：W1 老金标 7 篇 iou_avg 普遍 > 0.6，W2 新金标 15 篇中部分边界情况（多中标人/联合体/多分包）仍拉低整体指标，后续 W3 可通过提示词优化提升
