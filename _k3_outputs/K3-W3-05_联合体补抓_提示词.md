# K3-W3-05 联合体缺口补抓 任务提示词

## 任务背景

W3-01 标注的 90 篇公告中，真实联合体中标公告仅 1 篇（w3_award_070：哈工大牵头 + 2 家成员），未达 v4.1 第十章"≥2 篇真实联合体"的覆盖要求。需补抓 1-2 篇真实联合体中标公告并完成标注。

## 输入约束

- 数据源：ccgp.gov.cn（中国政府采购网）
- 公告类型：中标公告（award）
- 必须是**真实联合体中标**（非"接受联合体投标"条款）
- 特征词：正文含"牵头"、"联合体"、"成员单位"、"组成联合体"等
- 抓取频率：≤1 次/8 秒（约束 #14）
- 超时：15 秒
- 403 立即停止（约束 #15）

## 推荐做法

1. **WebSearch 找候选 URL**：
   - 搜索关键词：`site:ccgp.gov.cn 联合体 中标公告 2026`
   - 或：`中国政府采购网 联合体 中标结果`
   - 收集 3-5 个候选 URL

2. **用 fetch_public_notices.py 抓取**：
   - 把候选 URL 加入 LIST_URLS 或单独抓取
   - 输出到 `_w3_raw/w3_award_consortium_001.txt`（命名避开 001-090 已用编号）
   - 文件格式与现有 90 篇一致（前 4 行元数据 + `## ` 标记起的正文）

3. **验证是真实联合体**：
   - 正文必须含"牵头供应商"+"联合体成员"
   - 排除"不接受联合体投标"、"接受联合体投标"等招标条款
   - 至少 2 家成员单位

## 标注要求

补抓的公告按 K3-W3-01 同口径标注：
- 6 核心字段（project_identifier / purchaser_name / winner_name / amount / publish_date / bid_deadline）
- 偏移量基准：文件中第一个 `## ` 标记位置（相对坐标，从 0 开始）
- winner_name 用 `values[]` 标多中标人，联合体标 `partners` 字段
- 输出追加到 `tests/fixtures/gold/k3_annotations_batch2.json`（在元数据记录后、其他标注前插入）
- annotation_version: `k3-w3-01-v1-fixed3-consortium`

## 验收标准

- [ ] 补抓 1-2 篇真实联合体中标公告（非"接受联合体投标"条款）
- [ ] 每篇 6 字段全标，证据 spans 切片校验通过（基准=## marker）
- [ ] winner_name 多值（牵头 + 成员），partners 字段非空
- [ ] 文件格式与现有 90 篇一致
- [ ] JSON 合法，json.loads 通过
- [ ] 更新元数据 doc_count: 90 → 91/92

## 输出

- 原文：`_w3_raw/w3_award_consortium_001.txt`（如抓 2 篇则 _002.txt）
- 标注：追加到 `tests/fixtures/gold/k3_annotations_batch2.json`
- 报告：`_k3_outputs/K3-W3-05_交付报告.md`（含抓取 URL、验证证据、标注字段清单）

## 约束

1. **不修改现有 90 篇标注**，只追加新篇目
2. **不调用系统抽取 API**，从空白文本独立标注
3. **403 立即停止**，不要重试被封 IP
4. **如实报告**：如果 WebSearch 找不到合适 URL，如实报告"未找到真实联合体中标公告"，标记为待查
5. **分支**：在 feature/glm-w2-evidence 上提交，commit message: `feat(K3-W3-05): 补抓联合体中标公告补足缺口`
