## 标注规范（按 v4.1 10.3）

### 字段状态（必填）

| 状态 | 含义 | 计入主评测分母 |
|---|---|---|
| `present` | 正文中明确存在 | ✅ 是 |
| `absent` | 应用上可能存在，但当前可见内容中没有 | ✅ 是（空值误报率） |
| `not_applicable` | 对该公告类型不适用 | ❌ 单独统计 |
| `ambiguous` | 原文存在多个无法确定的候选值 | ❌ 单独统计 |
| `attachment_only` | 正文没有，但附件中可能存在 | ❌ 单独统计 |
| `unreadable` | 扫描、乱码等原因无法判定 | ❌ 单独统计 |

### 六类核心字段（必标，对齐 v4.1 第七章 7.1 节）

每篇公告标注以下 6 个字段（与代码 CORE_FIELD_NAMES 完全一致）：

1. `project_identifier` — 项目编号
2. `purchaser_name` — 采购人
3. `winner_name` — 中标人（招标公告标 not_applicable；联合体用 values[] 标 main + partners）
4. `amount` — 金额（区分 budget/award，多值用 values[] 数组）
5. `publish_date` — 发布日期
6. `bid_deadline` — 投标截止日期（中标/更正公告若未提及标 not_applicable）

> **附加字段（不计入核心评测，可选标）**：`project_name` — 项目名称

### 证据区间（present 字段必填）

每个 present 字段必须标注 `acceptable_evidence_spans[]`：
- `start`：证据起始字符偏移（基于清洗后纯文本，从 0 开始）
- `end`：证据结束字符偏移（exclusive）
- `text`：证据原文片段（用于校验）

**偏移量基准**：文件中第一个 `## ` 标记的位置（即清洗后正文起始位置，跳过前 4 行 `# ` 元数据 + 空行），字符偏移从该位置从 0 开始。校验脚本需以 `content.find("## ")` 为基准切片，否则全部 spans 会误判不匹配。

### 多值字段

- 多中标人：`values: [{"raw_value": "公司A", ...}, {"raw_value": "公司B", ...}]`
- 联合体：`values: [{"raw_value": "牵头公司", "partners": ["成员1", "成员2"]}]`
- 多分包金额：`values: [{"raw_value": "100万", "lot_id": "1"}, {"raw_value": "200万", "lot_id": "2"}]`

## 覆盖要求

- ≥10 篇招标、≥10 篇中标、≥5 篇更正
- ≥3 篇多分包（lot_id 不同）
- ≥2 篇多中标人（values 数组长度 > 1）
- ≥2 篇真实联合体（partners 非空）
- 如果 90 篇中没有真实联合体，如实报告"未覆盖联合体场景"

## 约束

1. **从空白文本标注**：只读原文，不调用系统抽取 API
2. **不参考系统输出**：不运行 eval_ablation.py / eval_evidence.py
3. **偏移量基于清洗后纯文本**：以文件中第一个 `## ` 标记位置为基准（跳过前 4 行 `# ` 元数据 + 空行）
4. **如实标注**：找不到的字段标 absent，不适用的标 not_applicable
5. **记录标注规范版本**：输出 JSON 顶部加 `"annotation_version": "k3-w3-01-v1"`
6. **记录标注时间**：每篇加 `"annotated_at": "2026-07-28T..."`
