## 背景

但对照标准逐条核验后发现 **4 处不合规**，且都不在代码逻辑本身：

1. **口径分叉（第八章第 6 类）**：仓库内 `data/bidagent.db` 是 **828** 条 tender，
   工作区是 **829** 条，而 README 与两份交付说明都写「829 篇」。
   ⇒ 任何人克隆后跑真实数据测试，拿到的都是 828 条；本文档里记的响应 sha256
   （`b76fd96c…` / 191064 B / 829 条）在干净克隆上**无法复现**。
2. **测试结果只写一个数（18.5 硬要求）**：只报了 `2452 passed`，
   缺 collected / failed / skipped 三项。
3. **未回答「测试能抓什么、抓不住什么」（铁律 9 / 18.1）**：交付说明里没有独立章节。
4. **15 类假完成清单未逐条过（第八章自查流程）**：只做了点状自查，没有落成交付件。

盲区显式声明、15 类逐条有结论、每条结论带强度。

## 实现要求

1. **数据口径收口**：仓库内库必须与文档声明的 829 条一致；提交前先跑
   `pragma integrity_check`，并复跑等价测试确认无回归。

4. **盲区必须显式写**：哪些断言能抓、哪些绝对抓不住。
5. **15 类逐条给结论**，命中即标「待查」，不许整表打勾了事。
