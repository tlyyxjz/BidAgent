## 一、项目概述

### 1.1 命题背景

超聚变数字能源技术有限公司在 2026 AI 先锋未来人才大赛提出的命题：

> 实现一个可运行的招投标信息聚合工具，用户通过自然语言输入查询需求，工具自动采集、清洗、去重并生成结构化的 Word 报告，支持定时推送和增量更新。

### 1.2 命题硬要求（6 项）

| # | 硬要求 | 实现状态 | 评分 |
|---|---|---|---|
| 1 | 意图解析 5 槽位（topic/region/time_range/frequency/trigger_type） | ✅ | 8/10 |
| 2 | ≥2 网站 + ≥1 登录态采集 | ✅ | 7/10 |
| 3 | SimHash 内容去重 | ✅ | 9/10 |
| 4 | 5 字段汇总（标题/发布时间/来源链接/核心内容/附件链接）+ Word 命名 | ✅ | 9/10 |
| 5 | 定时执行（cron 频率触发） | ✅ | 8/10 |
| 6 | 增量推送（已推送不重复） | ✅ | 8/10 |

### 1.3 技术栈

| 层 | 技术 | 用途 |
|---|---|---|
| Web 框架 | FastAPI 0.110+ | REST API |
| ORM | SQLAlchemy 2.x async + aiosqlite | 数据持久化 |
| 采集引擎 | Playwright | 浏览器自动化（含登录态） |
| LLM | DeepSeek V3 | 意图解析 |
| 调度 | APScheduler + croniter | cron 匹配 |
| 任务队列 | RQ + Redis | 异步任务 |
| 报告生成 | python-docx | Word 输出 |
| PDF 解析 | pdfplumber | 附件内容提取 |
| 去重算法 | SimHash + jieba | 64 位指纹 |
| OCR | ddddocr | 验证码识别 |
| 部署 | Docker + docker-compose | 多容器编排 |
| 限流 | SlowAPI | API 速率限制 |
| 日志 | loguru + request_id | 结构化日志 |

## 四、核心模块详解

### 4.1 意图解析模块

**位置**：`app/llm/parser.py`

**流程**：
1. 检查语义缓存（TTL 1h，LRU 1000）
2. 调 DeepSeek V3 API（timeout 30s）
3. JSON Schema 校验 + `data.pop("raw_query")` 防覆盖
4. 失败时降级到关键词正则
5. 写入缓存并返回 `ParsedFilters`

**5 槽位**：
- `topic`：主题（如"充电桩"）
- `region`：地区（如"上海"）
- `time_range`：时间范围（如"3m"）
- `frequency`：推送频率（cron 表达式）
- `trigger_type`：触发类型（immediate / scheduled）

**关键代码**：
```python
data.pop("raw_query", None)  # 防止 LLM 输出覆盖原始查询
parsed = ParsedFilters(raw_query=query, **data)
```

### 4.2 SimHash 去重模块

**位置**：`app/processors/simhash.py`

**算法**：
1. jieba 分词（退化方案：正则切词）
2. 每个词计算 MD5 64 位哈希
3. 等权累加（+1 / -1）→ 64 位指纹
4. 汉明距离 ≤ 3 视为重复

**集成点**：`tender_ingestor.py` 插入前查询最近 1000 条做汉明距离比对

**关键代码**：
```python
def compute_simhash(text: str) -> int:
    tokens = _tokenize(text)
    weights = [0] * 64
    for token in tokens:
        h = _hash64(token)
        for i in range(64):
            if h & (1 << i):
                weights[i] += 1
            else:
                weights[i] -= 1
    return sum(1 << i for i in range(64) if weights[i] > 0) & MASK64
```

### 4.3 调度模块

**位置**：`app/scheduler/subscription.py`

**核心函数**：
- `_is_cron_due(cron_expr, last_run, now)` - croniter 判断是否到期
- `get_unpushed_tenders(db, sub_id, filters)` - SQL NOT EXISTS 过滤已推送
- `trigger_subscription(sub_id, force=False)` - 触发推送（force=True 跳过 cron）

**关键代码**：
```python
def _is_cron_due(cron_expr, last_run, now):
    if last_run is None:
        itr = croniter(cron_expr, now)
        return itr.get_prev(datetime) <= now
    itr = croniter(cron_expr, last_run)
    return itr.get_next(datetime) <= now
```

### 4.4 Word 报告生成模块

**位置**：`app/report/docx_generator.py`

**结构**：
1. 封面（标题 + 查询条件 + 采集结果数 + 生成时间）
2. 报告摘要（平台数 + 预算总额 + 平均预算）
3. 项目明细表（5 字段：标题/发布时间/来源链接/核心内容/附件链接）
4. 反幻觉校验章节（关键事实提取 + 一致性校验）
5. 分析建议
6. 页脚

**文件命名**：`{用户问题}_{YYYYMMDDHHmm}.docx`

**关键代码**：
```python
async def generate_report(filters, items, job_id=None):
    loop = asyncio.get_running_loop()
    return await loop.run_in_executor(
        None, _generate_report_sync, filters, items, job_id
    )
```

### 4.5 反幻觉校验模块

**位置**：`app/processors/hallucination_checker.py`

**校验项**：
- 招标编号正则匹配
- 预算金额数值校验
- 截止日期格式校验
- 核心内容字段必填
- 关键事实一致性比对（core_content vs 报告文本）

**输出**：
- `score`：0-100 分（越高越可信）
- `warnings`：警告列表
- `critical_issues`：严重问题列表

### 4.6 PDF 附件解析模块

**位置**：`app/processors/pdf_parser.py`

**功能**：
1. pdfplumber 提取文本 + 表格
2. 正则提取 8 个关键字段（项目名/编号/预算/截止时间/招标人/代理/联系人/电话）
3. `enrich_tender_from_pdf()` 把字段补充到 Tender.core_content

**集成点**：`attachment_downloader.download_attachment(parse_pdf_content=True)`

### 4.7 多 Agent 协作模块

**位置**：`app/agents/coordinator.py`

**4 个 Agent**：
1. `intent_agent` - 调 `parse_query` 解析意图
2. `collect_agent` - 调 `collect_new_tenders` 采集
3. `clean_agent` - 统计去重数量 + 字段校验
4. `report_agent` - 调 `generate_report` 生成报告

**特点**：
- 纯 Python 实现，不依赖 langgraph
- 完整执行轨迹（`ExecutionTrace` 记录每个 Agent 耗时、输入输出摘要）
- 失败时终止整个图，记录 `_last_error`

## 五、安全设计

### 5.1 输入侧安全

| 风险 | 防护措施 | 位置 |
|---|---|---|
| 路径遍历 | `_sanitize_filename` + `os.path.basename` + 最终路径校验 | attachment_downloader.py |
| SSRF | `ipaddress` 拦截 private/loopback/link-local/reserved/multicast | attachment_downloader.py |
| SQL 注入 | SQLAlchemy ORM 参数化查询 | 全部 |
| LIKE 通配符 | `_escape_like` 转义 % _ \ | subscription.py / tender.py |
| LLM 输出覆盖 | `data.pop("raw_query", None)` | llm/parser.py |
| CORS 滥用 | 默认仅 localhost，启动时检查 `*` 警告 | main.py |
| 文件大小 | 附件 50MB 上限 + PDF 10MB 上限 | attachment_downloader.py |

### 5.2 数据侧安全

| 风险 | 防护措施 |
|---|---|
| 密码泄露 | bcrypt 哈希存储 |
| API Key 泄露 | SHA256 hash 落库 + `secrets.compare_digest` 常量时间比较 |
| 联系人隐私 | phone / email SHA256 hex 存储 |
| 时序攻击 | `secrets.compare_digest` 防时序差异 |

### 5.3 速率限制

| 维度 | 限制 |
|---|---|
| 免费 API Key | 5 次/天 |
| 付费 API Key | 不限 |
| 全局 | SlowAPI 中间件 |

## 六、性能设计

### 6.1 异步 IO

- 所有 IO 操作（DB / HTTP / 文件）使用 async/await
- 同步库（pdfplumber / python-docx）通过 `run_in_executor` 包装
- 文件写入用 `aiofiles` 避免阻塞

### 6.2 缓存

| 缓存 | 实现 | TTL | 容量 |
|---|---|---|---|
| LLM 语义缓存 | dict + TTL + LRU | 3600s | 1000 |
| Playwright 浏览器 | 单例复用 | - | 1 |

### 6.3 数据库优化

| 优化 | 实现 |
|---|---|
| 增量推送 | SQL NOT EXISTS 在数据库层面过滤 |
| SimHash 候选集 | 取最近 1000 条做汉明距离比对 |
| 连接池 | 非 SQLite 显式配 pool_size=10 / max_overflow=20 / pool_recycle=3600 |

### 6.4 批量操作

- PushLog 批量插入 `db.add_all([...])`
- 附件批量下载 `download_attachments_batch`
- 招标信息批量入库 `ingest_scrape_result` 支持列表
