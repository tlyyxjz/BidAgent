### 1.2 主要差异点

1. **完整版定位为"全功能 SaaS 平台"**：多了套餐限制（plans.py）、用户自助注册（user_auth.py）、代理池健康检测（proxy_manager.py）、反检测浏览器（anti_detect.py）、30+ 数据源（sources.py）、Cloudflare 部署。
2. **当前版本定位为"招投标信息聚合工具"**：聚焦命题硬要求，已有千里马登录态采集、Webhook 推送、多 Agent 协作、Sol 修复链。
3. **完整版新增的 AI 创新模块（废标引擎 / BOQ / 供应商风控）写了但未挂载到 main.py**，实际是"展示用代码"。
4. **测试覆盖度**：完整版多一整套 `tests_deep/`（含 3 档安全测试），当前版本只有标准 pytest 测试。

## 3. 详细分析（每个独有模块）

### 3.1 `app/api/ai_features.py` — AI 创新功能路由

- **功能简介**：封装 `/api/ai/risk-analysis`、`/api/ai/boq-analysis`、`/api/ai/supplier-risk` 三个端点，分别调用 `risk_engine` / `boq_engine` / `supplier_risk`。
- **代码质量**：代码简洁（45 行），Pydantic 模型规范，请求/响应格式统一。
- **是否挂载**：❌ **未挂载**。完整版 `main.py` 第 23-29 行的 router 列表只有 `admin_router / scrape_router / subscribe_router / tender_router / sources_router / proxy_router / ui_router`，没有 `ai_features.router`。访问 `/api/ai/*` 会返回 404。
- **严重 bug**：路由未注册，所有 AI 创新功能对外不可达。

### 3.2 `app/api/user_auth.py` — 用户注册/登录

- **功能简介**：注册、登录、获取 profile、更新 SMTP 配置。
- **代码质量**：⚠️ **多个严重安全问题**。
- **是否挂载**：❌ **未挂载**。完整版 `main.py` 没有 `from app.api.user_auth import router`。
- **严重 bug**：
  - **密码用 SHA256 无 salt**（第 19-20 行）：
    ```python
    def _hash_password(password: str) -> str:
        return hashlib.sha256(password.encode("utf-8")).hexdigest()
    ```
    无 salt + SHA256（fast hash）—— 易受彩虹表和 GPU 暴力破解。正确做法应使用 bcrypt/argon2。
  - **用 `X-User-Email` 头认账**（第 93、131 行）：
    ```python
    email = request.headers.get("X-User-Email", "")
    ```
    `get_profile` / `update_smtp` 端点完全信任客户端传入的邮箱头，**任何人可以伪造 header 冒充任意用户读取/修改 SMTP 配置**。
  - **Token 不持久化**（第 74-83 行）：登录返回 `sess_xxx` token，但既没存数据库也没存 Redis，下次请求无法验证 token 有效性——这是为什么改用 `X-User-Email` 头的原因，但补救方案是错的。

### 3.12 `app/processors/dedup.py` — SimHash 128 位去重

- **功能简介**：310 行。基于 `simhash` 库（第三方包），128 位指纹，Hamming 阈值 32；含 `compute_simhash` / `is_similar` / `build_index_from_db` / `find_duplicates` / `backfill_simhash` / `has_duplicates` / `similarity_ratio`。
- **代码质量**：✅ 优秀。CPU 密集计算通过专用 `ThreadPoolExecutor` 放入线程池；游标分页避免 offset 偏移；日志带 tender_id 上下文。
- **是否挂载**：⚠️ **未挂载到任何 endpoint**。完整版 `tender_ingestor.py` 没有调用 `dedup.py`——它继续使用 `simhash.py`（64 位版本）。
- **严重 bug**：
  - **与当前版本的 `simhash.py`（64 位）冲突**：当前版本 `processors/simhash.py` 已有 64 位 SimHash 实现（`MASK64`、`hamming_distance`、`compute_simhash`），且被 `tender_ingestor.py` 第 28 行 `from app.processors.simhash import find_duplicate_in_iter` 调用。完整版的 `dedup.py` 是另一套 128 位实现，**两者并存会导致算法不一致**（64 位 vs 128 位指纹不互通，Hamming 阈值也不同：当前版本阈值在 simhash.py 中，完整版 dedup.py 用 32）。

### 3.13 `app/processors/report_engine.py` — 综合报告引擎

- **功能简介**：127 行。聚合 `risk_engine` + `boq_engine` + `supplier_risk`，输出加权综合评分 + 结论 + 推荐建议。
- **代码质量**：⚠️ 中等。
- **是否挂载**：⚠️ **未挂载**。是定义了但未使用的工具函数。
- **严重 bug**：
  - 第 55 行 `total = 100 - (risk_score * 0.5) + (boq_score * 0.2) - (supplier_score * 0.3)`——加权公式可疑：boq_score 越高代表清单越规范，应该加分，但加 0.2 倍可能让 total 超过 100（虽然后面有 `min(100, ...)` 兜底）。
  - 第 58-61 行 `if not boq_report.get("items"): total -= 20`——空清单扣 20 分，但 BOQ 引擎对未提取到数据的返回 score=100，逻辑矛盾。

### 3.14 `app/processors/risk_engine.py` — 废标风险引擎

- **功能简介**：166 行。18 条规则，覆盖排他性资质、付款风险、交货期、资质门槛、DeepSeek V4 Pro 联合规则（本地化业绩+资格叠加、★技术参数、联合体分包矛盾、否决条款密集）；输出 RiskReport 含 score + risk_items + qualification_gaps。
- **代码质量**：⚠️ 中等。
- **是否挂载**：✅ 通过 `ai_features.py` 间接挂载——但 `ai_features.py` 本身未挂载。
- **严重 bug**：
  - 第 99-104 行多词组合规则逻辑错误：
    ```python
    if len(keywords) > 1 and any(kw in keywords[1:] for kw in ["*", "★"]):
        if any(kw in content for kw in keywords):  # ← 应为 all
            match = True
    ```
    `["★", "*"]` 规则本意是"全部技术参数标注星号"，但用 `any(kw in content for kw in keywords)` 只要 content 中出现"★"或"*"就命中——**正常技术文档中"1*2=2"或"3★酒店"都会误判**。

## 7. 总结

### 7.1 一句话结论

**完整版是"广而浅"的全功能 SaaS 框架，写了大量展示用代码但多个核心模块未挂载到 main.py（ai_features / user_auth / anti_detect / rss_collector / dedup / report_engine 全部是 dead code）；当前版本是"窄而深"的命题工具，已应用 Sol 修复链且 211 测试全过——应选择性吸收完整版的"30+ 数据源注册表 + 高级代理池 + 安全深度测试"三项高价值模块，其余模块（AI 引擎、user_auth、dedup、anti_detect）因存在严重 bug 或与现有实现冲突，不建议直接吸收。**
