## K-1：方案 PPT 制作（30 页 .pptx）

### 任务目标

制作 30 页方案 PPT，用于 GOAI 大赛初赛提交。PPT 必须是 `.pptx` 格式，评委拿到就能打开。

### 输入

- **设计文档**：`docs/superpowers/specs/2026-07-20-bidagent-goai-design.md`（完整阅读）
- **赛事要求**：GOAI 无界应用赛道 AI+金融方向，初赛提交内容为「作品简介 + 方案 PPT/PDF + 可选原型或视频」
- **评审维度**：行业场景价值 / Agent 能力与任务闭环 / 产品体验与 Demo 完成度 / 技术实现深度与工程可复现性 / 安全、合规与开放复用价值

### PPT 大纲（30 页）

#### 第一部分：开场（3 页）

1. **封面**：BidAgent — 智能标讯助手 / 智汇标讯团队 / GOAI 大赛 / 日期
2. **团队介绍**：智汇标讯 / 成员背景 / 技术栈
3. **目录**：6 大章节

#### 第二部分：问题与场景（4 页）

4. **行业痛点**：招投标信息分散在 4+ 平台 / 供应链金融数据孤岛 / 人工浏览耗时易遗漏
5. **目标用户**：供应链金融机构 / 银行对公业务 / 保理公司 / 投标企业
6. **场景故事**：某银行信贷员评估供应商信用 → 用 BidAgent 5 分钟生成报告（含 BOQ 异常 + 废标风险 + 供应商信用评分）
7. **市场机会**：招投标数据服务市场规模 / 供应链金融市场规模

#### 第三部分：产品方案（6 页）

8. **产品定位**：招投标数据服务商 / 决策辅助工具 / AI Agent 应用
9. **六 Agent 协同架构图**：意图 → 采集 → 加工 → 质检 → 金融分析 → 交付（用流程图展示）
10. **Agent 职责详解**：每个 Agent 一行说明 + 核心能力
11. **金融分析 Agent 详解**：BOQ 异常检测 + 废标风险预警 + 供应商信用评分（三维度）
12. **任务闭环示例**：用户输入"找上海最近7天的IT采购项目" → 六 Agent 协作 → Word 报告 + 邮件推送
13. **交互流程**：聊天 UI 输入 → Agent 进度可视化 → 报告下载 + 邮件通知

#### 第四部分：技术实现（8 页）

14. **技术栈**：Python 3.13 / FastAPI / Playwright / DeepSeek V3 / SimHash / python-docx / Docker
15. **Agent 协作框架**：纯 Python 轻量级实现（不依赖 langgraph）/ 状态 dict 传递 / 顺序执行 + 条件分支
16. **技术亮点 1：浏览器反检测 + 登录态持久化**：patchright + stealth init_script / Playwright storage_state / 千里马 16 cookies 实测通过
17. **技术亮点 2：SimHash 64 位去重 + 反幻觉校验**：三阶段批量 + SAVEPOINT / 金额日期归一化 + 事实比对
18. **技术亮点 3：BOQ 报价异常检测**：20 类基准价格库 / 市场均价 ±std 判定 / 修复完整版双向包含 bug
19. **技术亮点 4：供应商信用评分**：三维度（活跃度 + 中标率 + 偏离度）/ 加权 30/40/30 / 去掉完整版伪造联邦学习
20. **技术亮点 5：at-least-once 推送 + content_hash 幂等**：金融数据不漏发不重发 / 30 分钟去重窗口
21. **技术亮点 6：安全防护体系**：SSRF 三层防护 / 邮件头注入防护 / HMAC 签名 / 路径穿越防护 / LIKE 注入防护

#### 第五部分：Demo 与验证（4 页）

22. **Demo 截图**：聊天 UI / Agent 协作进度 / Word 报告样例 / 邮件推送
23. **实测数据**：千里马登录态 16 cookies / 163 SMTP 实发邮件成功 / 221 测试全过
24. **测试覆盖**：核心算法 + 企业级特征 + 安全测试 + 金融模块测试
25. **部署方案**：Docker 多阶段构建 / non-root 用户 / healthcheck / 环境变量配置

#### 第六部分：合规与开放（4 页）

26. **合规边界**：数据来源合规（政府公开 + 用户授权）/ 隐私保护 / 风险提示 / 行业边界 / AI 反幻觉
27. **开放复用价值**：Agent 协作框架 / ScrapeTemplate 模板架构 / SimHash 去重组件 / 反幻觉校验组件 / BOQ 基准价格库 / 安全防护体系
28. **后续迭代计划**：复赛（WebUI + RAG）/ 决赛（路演）/ 长期（商业化 + 开源）
29. **团队联系方式**：邮箱 / GitHub

#### 结尾（1 页）

30. **致谢**：感谢 GOAI 组委会 / 评委 / 开源社区

### 设计风格要求

- **配色**：科技蓝 + 金融金（深蓝主色 #1A365D + 金色点缀 #D69E2E + 浅灰背景 #F7FAFC）

## K-3：合规边界文档

### 任务目标

基于设计文档第 8 节，输出独立的合规边界文档，用于初赛提交和答辩准备。

### 输入

- **设计文档第 8 节**：`docs/superpowers/specs/2026-07-20-bidagent-goai-design.md` 第 8 节

### 文档大纲

1. **数据来源合规**
   - 政府公开数据（ccgp / ggzy / chinabidding）
   - 用户授权数据（千里马，用户提供个人账号）
   - 不绕过付费墙 / 不采集个人隐私

2. **隐私保护**
   - 不采集个人隐私数据（身份证 / 手机号 / 住址）
   - 供应商信用评分基于公开招投标历史数据
   - 用户账号密码加密存储（Playwright storage_state）

3. **风险提示**
   - BOQ 异常检测 / 废标风险 / 供应商信用评分均为决策辅助
   - 报告标注「AI 生成，仅供参考，决策请人工复核」
   - 邮件推送含免责声明

4. **行业边界**
   - 不提供金融建议
   - 不承担金融决策责任
   - 不持有用户资金
   - 不做金融交易撮合
   - 定位为数据服务商

5. **AI 反幻觉保障**
   - 金额归一化（万元 / 亿元 / 元统一）
   - 日期归一化（多种格式统一）
   - 事实比对（LLM 提取的关键事实必须在原文中找到）
   - 溯源引用（每条数据标注来源 URL + 提取片段）

6. **免责声明**（正式法律措辞）

### 输出文件

- `docs/compliance.md`（合规边界文档，约 2000 字）
