## 一、项目概述

标小智 招标公告智能解析系统，提供以下核心能力：

| 模块 | 说明 |
|---|---|
| 公告采集 | 支持中国政府采购网、千里马等多平台公告抓取 |
| 智能解析 | 基于 LLM 的结构化字段抽取，带证据溯源 |
| 版本追踪 | 公告变更历史记录与 diff 对比 |
| 组织画像 | 采购方/中标方实体画像分析 |
| Web Demo | 交互式前端演示页面 |

## 三、快速启动（Docker 一键部署）

### 步骤 1：获取代码

```bash
git clone <repository-url>
cd BidAgent
```

### 步骤 2：配置环境变量

```bash
# 复制环境变量模板
cp .env.example .env
```

生成必需的密钥：

```bash
# 生成 SECRET_KEY（64 字符 hex）
python -c "import secrets; print(secrets.token_hex(32))"

# 生成 ADMIN_SECRET（至少 8 字符）
python -c "import secrets; print(secrets.token_urlsafe(24))"
```

将生成的值填入 `.env` 文件：

```env
SECRET_KEY=<上面生成的 64 字符 hex>
ADMIN_SECRET=<上面生成的 admin 密钥>
```

> 详细环境变量说明见 [第四章](#四环境变量配置详解)。

### 步骤 3：启动服务

```bash
docker compose up -d --build
```

首次构建需要下载基础镜像和 Python 依赖，约 5-10 分钟。

### 步骤 4：查看启动状态

```bash
# 查看容器状态
docker compose ps

# 实时查看日志
docker compose logs -f biaoxiaozhi
```

预期输出（所有服务 `State` 为 `running` / `healthy`）：

```
NAME                IMAGE              COMMAND                  SERVICE             CREATED             STATUS
biaoxiaozhi          bidagent-biaoxiaozhi  "uvicorn app.main:..."  biaoxiaozhi          2 minutes ago       Up 2 minutes (healthy)   0.0.0.0:8000->8000/tcp
redis               redis:7            "docker-entrypoint..."  redis               2 minutes ago       Up 2 minutes (healthy)   6379/tcp
worker              bidagent-worker     "python -m rq work..."  worker              2 minutes ago       Up 2 minutes
```

## 四、环境变量配置详解

### 4.1 必需配置

| 变量 | 说明 | 示例值 |
|---|---|---|
| `SECRET_KEY` | JWT 签名密钥，64 字符 hex | `a1b2c3...`（用 `secrets.token_hex(32)` 生成） |
| `ADMIN_SECRET` | 管理员接口密钥，至少 8 字符 | `changeme123` |
| `DATABASE_URL` | 数据库连接 URL | `sqlite+aiosqlite:///./data/bidagent.db` |
| `REDIS_URL` | Redis 连接 URL | `redis://redis:6379/0`（Docker 内） |

### 4.2 可选配置

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PROXY_LIST` | 空 | 代理池列表，逗号分隔 |
| `PLAYWRIGHT_HEADLESS` | `true` | Playwright 是否无头模式 |
| `PLAYWRIGHT_TIMEOUT_SECONDS` | `30` | 页面加载超时（秒） |
| `FREE_TIER_DAILY_LIMIT` | `5` | 免费套餐每日请求数限制 |
| `CORS_ORIGINS` | `*` | CORS 允许的源 |
| `SENTRY_DSN` | 空 | Sentry 错误上报 DSN（可选） |

### 4.3 SMTP 邮件推送配置（可选）

| 变量 | 说明 |
|---|---|
| `SMTP_HOST` | SMTP 服务器地址 |
| `SMTP_PORT` | 端口（587 / 465） |
| `SMTP_USER` | SMTP 用户名 |
| `SMTP_PASSWORD` | SMTP 密码 / 授权码 |
| `SMTP_USE_TLS` | `true`=587 STARTTLS，`false`=465 SSL |
| `SMTP_FROM_ADDR` | 发件人邮箱 |
| `SMTP_FROM_NAME` | 发件人显示名称 |

### 4.4 反检测浏览器配置（可选）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ANTI_DETECT_ENABLED` | `true` | 是否启用反检测浏览器 |
| `ANTI_DETECT_HEADLESS` | `true` | 无头模式 |
| `ANTI_DETECT_NO_SANDBOX` | `false` | 禁用沙箱（Docker 内需设为 true） |
| `BROWSER_POOL_SIZE` | `2` | 浏览器池大小 |

### 4.5 千里马登录配置（可选）

| 变量 | 说明 |
|---|---|
| `QIANLIMA_USERNAME` | 千里马账号 |
| `QIANLIMA_PASSWORD` | 千里马密码 |

## 七、常见问题排查

### Q1：`docker compose build` 失败，提示网络错误

**原因：** pip 下载依赖超时。
**解决：** 配置 pip 镜像源，或使用代理：

```bash
# 临时使用代理构建
docker compose build --build-arg HTTP_PROXY=http://proxy:port
```

### Q2：容器启动后立即退出

**排查步骤：**
```bash
# 查看具体日志
docker compose logs biaoxiaozhi

# 常见原因：SECRET_KEY 未配置或格式错误
docker compose logs biaoxiaozhi | grep -i "secret"
```

### Q3：Playwright 浏览器无法启动

**原因：** Docker 内缺少浏览器依赖或权限不足。
**解决：**
- 确保 `.env` 中 `ANTI_DETECT_NO_SANDBOX=true`
- 确认基础镜像已安装系统依赖

### Q4：Redis 连接失败

**排查：**
```bash
# 检查 Redis 容器是否运行
docker compose ps redis

# 测试连接
docker compose exec redis redis-cli ping
# 预期: PONG
```

### Q5：无法访问 8000 端口

**排查：**
```bash
# 检查端口是否监听
netstat -an | findstr 8000

# Windows 检查防火墙
# 或尝试使用 127.0.0.1 替代 localhost
```

### Q6：静态页面 404

**原因：** static 目录未挂载或路径不对。
**解决：** 确认 `docker-compose.yml` 中 volumes 配置正确，或重新构建镜像。
