# 标小智 路演讲稿（5 分钟）

**队伍**：标小智（徐浚钊、王祯明）
**赛道**：GOAI 2026 · AI+金融
**定位**：面向供应链金融贷前尽调的可验证招投标数据引擎
**时长**：5 分钟（正文约 1300 字，按 4.3 字/秒配速 ≈ 300 秒 ±15 秒）

---

## 开场（30 秒）

各位评委好，我是标小智团队的徐浚钊。我们带来的作品是 **标小智**——一个面向供应链金融贷前尽调的**可验证招投标数据引擎**。

一句话概括：**用户说一句话，六个 Agent 协同完成采集、校验、分析，输出一份每个数字都能点回原文的可验证尽调报告。**

【记忆点 1】**"标小智的每个数字，都能点回公告原文。"** 这句话请评委记住，后面的评测数据就是为它准备的。

---

## 痛点（40 秒）

供应链金融的尽调场景里，风控人员核查一家供应商的中标记录，要面对三个痛点：

1. **信息分散**——中标记录散布在政府采购网、公共资源交易平台等 30 多个招投标信息平台，人工逐站检索；
2. **可信度无保障**——通用大模型直接问"这家公司靠不靠谱"，答案是生成的，没有依据，金融机构不敢用；
3. **风险靠经验**——报价是否异常、有没有废标风险，全靠老师傅肉眼判断，无法规模化。

标小智要解决的第二个痛点是核心：**AI 输出不可信，是我们这个赛道最大的拦路虎。**

---

## 解决方案：六 Agent 协同（60 秒）

标小智采用六 Agent 协同架构，一句话需求进入，六个 Agent 依次接力：

**① 意图解析 Agent**：把自然语言拆成结构化条件，LLM 失败时自动降级正则兜底；
**② 采集执行 Agent**：并行抓取 4 个平台，8 秒间隔、默认 UA、遇到 403 立即停手，合规优先；
**③ 数据加工 Agent**：SimHash 去重、字段归一化；
**④ 质量保障 Agent**：这是我们的护城河——LLM 提取字段时必须同时输出证据片段，确定性引擎在原文中定位证据，金额、日期、编号三类字段再做确定性校验；
**⑤ 金融分析 Agent**：三大差异化能力的载体，下一部分展开；
**⑥ 报告交付 Agent**：生成 Word 报告，cron 定时推送。

六个 Agent 全程留痕：每次 LLM 调用记录 request_id、response_hash、tokens 和延迟，**可复现、可审计**。

---

## 三大差异化（70 秒）

标小智不做信息搬运工，做的是金融级分析。三个差异化能力：

**第一，BOQ 报价异常检测。** 基于 32 类采购品类的基准价格库，自动识别低于品类均价的可疑报价——供应商 4200 块投笔记本电脑，而市场均价 6500，系统自动标红预警。

**第二，废标风险预警。** 18 条规则覆盖排他性资质、付款条件、交货期等关键维度，投标之前先排雷。

**第三，供应商公开活动观察。** 从中标活跃度、公开中标集中度、废标公告关联、明确投标否决、信息冲突观察、高频共现提示六个维度生成观察信号（对齐 observation_signals.py 口径），每个信号都能下钻到支撑它的中标公告原文——观察不是黑盒，是可解释的。严格不输出信用评分（v4.1 §9.1）。

---

## 工程质量与评测（60 秒）

说一千道一万，AI 可不可信要看数据。我们用 **99 篇真实招投标公告金标**（W2 22 篇 + W3 77 篇，594 个字段全部人工验证）做了四组消融实验 A/B/C/D，金标口径采用 budget+award 多值（支持报价偏离度观察）：

- **无依据输出率：A 组（无证据 prompt）100%，D 组（完整流水线）0%**——证据验证流水线把无依据输出完全压掉；
- **C/D 组 evidence_precision = 100%**：系统输出的每一条证据都能在原文中定位；
- **证据定位召回率 67.96%**，证据边界 IoU avg 0.5339、中位数 0.71、95 分位 1.0——找到的证据，边界基本就是对的；
- **字段精确率 92.17%**（D 组 594 字段），四组消融分层符合预期。

【记忆点 2】**"无依据输出，从 100% 压到 0%。"** 这就是证据验证流水线的价值。

工程侧：2031 项 pytest 全部通过（含 parametrize 展开），代码覆盖率 88.85%，证据入库验证零错误，金额、日期、编号三类确定性校验全量覆盖。

## 总结（40 秒）

标小智的定位不是又一个招投标聚合工具，而是 **AI+金融的可验证招投标数据引擎**：

- 对金融机构，它是可审计的尽调助手；
- 对投标企业，它是 BOQ 报价和废标风险的体检仪；
- 对评委，它是我们交给开源社区的作品——Apache 2.0 协议，六大组件全部可复用。

【记忆点 3】**"不做信息搬运，做可验证的证据链。"** 这是标小智和所有竞品最大的不同。

感谢评委，欢迎提问。

## 答辩问答（15 题）

### Q1：为什么自研六 Agent，不用 LangGraph？（技术选型）
A：我们的场景是线性接力 + 条件降级，纯 Python 约 200 行即可实现，执行轨迹、耗时、错误完全可控。LangGraph 引入额外依赖和兼容性风险，对当前规模是过度设计。后续若出现分支/回环编排需求，再评估迁移。

### Q2：LLM 为什么选 deepseek-v4-flash？（技术选型）
A：三个原因：成本（99 篇 ×4 组消融实验 tokens 约 133 万，总成本 ¥1.99）、速度（平均延迟约 6-8 秒/篇）、JSON 输出稳定性。所有调用记录 model 标识、request_id、tokens、延迟，可复现。

### Q3：证据定位的技术原理是什么？
A：确定性证据搜索引擎，L1-L5 五级降级匹配：精确匹配 → 空白归一 → 全半角归一 → 金额/日期格式变体 → 模糊匹配。99 篇评测中 recall 67.96%，IoU 的 avg=0.5339/P50=0.71/P95=1.0。

### Q4：观察信号的可解释性怎么保证？（信号可解释性）
A：五维加权（集中度/金额/频率/地域/采购人，权重 25/20/20/15/20，对齐 observation_signals.py 口径），每个信号都可下钻到具体中标公告和证据片段。评委看到的不只是观察度 75.2，而是"为什么是这个值"——这正是证据流水线的延伸价值。

### Q5：BOQ 基准价格库从哪来？数据会不会过时？
A：来自系统持续采集的历史中标公告，按 32 类品类聚合计算均价，滚动更新。采集量越大基准越准，这是数据飞轮，也是壁垒。

### Q6：废标风险 18 条规则的依据？
A：来自《政府采购法》第二十二条、87 号令等公开法规和真实废标案例归纳，每条规则在报告中标注命中依据，不构成法律意见，仅供人工参考。

### Q7：采集合规吗？会不会被封？（数据合规）
A：三条红线写进代码：默认 UA 不带任何绕过手段、请求频率 ≤ 1 次/8 秒、遇到 HTTP 403 立即停止。只采集公开发布的公告信息，不碰登录后数据和反爬保护内容。

### Q8：观察信号算不算征信业务？合规边界在哪？（数据合规）
A：不构成征信。数据全部来自公开招投标公告，不采集个人隐私和金融数据；报告含显著免责声明"AI 生成仅供参考，最终决策请人工复核"；定位为辅助工具而非决策主体。

### Q9：商业模式是什么？谁付费？（商业模式）
A：To B SaaS。目标客户是供应链金融机构、保理公司和大型企业的采购风控部门，按订阅收费。前期先以投标企业的"标前体检"场景切入，决策链短、付费意愿明确。

### Q10：如何扩展到更多平台？（多平台扩展）
A：模板化设计。新平台实现 BaseTemplate 接口（选择器 + 列表规则 + 等待条件），注册即可接入。当前 4 个平台已验证该机制，新增平台不改核心代码。

### Q11：field_precision 为什么是 A>B>C？流水线反而拉低精度？（必问题）
A：field_precision 只统计字段值是否命中，四组结果为 A 91.97% / B=C 92.58% / D 92.17%，差异在 1 个百分点内。衡量流水线价值的核心指标是 unjustified_rate（A 100% → D 0%）和 evidence_precision（C/D 100%），这两个指标四组分层完全符合预期。D 组完整流水线在保持 92.17% 字段精确率的同时，把无依据输出压到 0%。

### Q12：金标数据质量怎么保障？
A：双标注员独立标注 + 字段级仲裁。99 篇金标、594 个字段全部机器验证指向正确原文；第二标注员仲裁同意率 78.03%，29 处分歧全部归因分类（代理机构混入、金额口径等），仲裁表随代码开源。

### Q13：826 项测试的可信度？会不会是摆设？
A：测试覆盖 LLM 客户端、证据定位、金额/日期/编号校验、多值字段、增量推送等关键路径；2031 项 pytest 全部通过（含 parametrize 展开），代码覆盖率 88.85%。W3 已完成覆盖率补强目标。

### Q14：LLM 完全挂了系统还能跑吗？
A：能降级。意图解析有正则兜底；提取失败标记 success=False 并记录 error_message，不吞异常；报告照常生成并标注失败字段，绝不编造数据。

### Q15：和千里马、标信通这类产品的差异？
A：它们是信息聚合工具，解决"找到公告"；标小智解决"公告可信 + 供应商可信"——证据可定位、评分可解释、风险可预警。定位不同，能力互补，我们甚至可以消费它们的聚合结果做分析层。
