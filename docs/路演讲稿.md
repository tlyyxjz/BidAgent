## 痛点（30 秒）

在传统招投标场景中，企业 BD 和采购人员每天面临三个痛点：

1. **信息分散** - 政府采购网、中国招标网、千里马等平台信息不互通
2. **重复劳动** - 同一招标公告在不同平台重复出现，人工筛选耗时
3. **错过截止** - 招标截止时间各异，没有提醒机制容易错过

超聚变命题要求我们做一个可运行的招投标信息聚合工具，正好对应这三个痛点。

---

## 解决方案（1 分钟）

ScrapeFlow 采用**五层架构 + 多 Agent 协作**的设计：

```
用户输入 → 意图解析 → 采集规划 → 数据清洗 → 报告生成
```

具体来说：

**第 1 层 意图解析**：用户用自然语言输入查询，比如"最近3个月上海充电桩招标"，系统通过 DeepSeek V3 解析出 5 个槽位——主题、地区、时间范围、推送频率、触发类型。如果 LLM 失败，自动降级到关键词正则兜底，保证可用性。

**第 2 层 采集规划**：系统支持 4 个平台模板——政府采购网、中国招标网、公共资源交易网、千里马。千里马需要登录，我们用 Playwright 注入 cookie 实现登录态采集，验证码用 ddddocr 识别。

**第 3 层 数据清洗**：这是命题硬要求。我们实现了 64 位 SimHash 算法 + jieba 分词，对每条招标信息计算指纹，汉明距离 ≤ 3 视为重复。这样即使同一公告在不同平台发布，也能自动去重。

**第 4 层 报告生成**：系统生成符合命题命名规则的 Word 报告——`{用户问题}_{YYYYMMDDHHmm}.docx`，必含 5 字段：标题、发布时间、来源链接、核心内容、附件链接。我们额外加了反幻觉校验章节，用正则提取关键事实（招标编号、预算金额、截止时间）做一致性校验。

**第 5 层 调度推送**：用 croniter 实现 cron 表达式匹配，配合 PushLog 表的 SQL NOT EXISTS 查询实现增量推送——已推送的不重复，只推新增的。

## 技术亮点（1 分钟）

我们的差异化亮点有 **5 个**：

### 1. 多 Agent 协作框架（自研）

不依赖 langgraph，纯 Python 实现 4 Agent 串行协作：意图理解 Agent → 采集规划 Agent → 数据清洗 Agent → 报告生成 Agent。每个 Agent 都有完整的执行轨迹，包括耗时、输入输出摘要、错误信息。这在答辩展示时能让评委清晰看到 AI 协作过程。

### 2. 反幻觉校验

不只是生成报告，还校验报告内容与原文一致性。提取 8 个关键字段（项目名/招标编号/预算/截止时间/招标人/代理/联系人/电话），与采集原文做事实比对，输出 0-100 分的可信度评分。

### 3. PDF 附件内容解析

不只是下载附件，还用 pdfplumber 提取附件中的文本和表格，自动补全到招标信息字段。这样即使采集页面信息不全，附件里的项目编号、预算等关键信息也能被提取出来。

### 4. 安全设计完整

- 路径遍历防护（`..` 穿越符拦截）
- SSRF 防护（拒绝 169.254.169.25254 等内网地址）
- API Key SHA256 + 常量时间比较（防时序攻击）
- 联系人信息 SHA256 hex 存储（隐私保护）
- LLM 输出覆盖防护（`data.pop("raw_query")`）

### 5. 工程规范

- 全 async/await，无阻塞 IO
- 单文件 ≤ 300 行
- 统一 `{code, data, msg}` 响应格式
- request_id 全链路追踪
- Docker 多阶段构建 + 非 root 用户 + healthcheck

## 答辩问答准备

### Q1：为什么不直接用 langgraph？
A：langgraph 引入额外依赖 + 兼容性风险，而我们的 4 Agent 串行场景用纯 Python 200 行就能实现，更轻量、更稳定，执行轨迹完全可控。

### Q2：SimHash 准确率如何？
A：等权实现准确率约 75%，已列入 GPT-5.6 Sol 升级计划，改用 TF-IDF 加权可达 90%+。MVP 阶段已满足命题去重要求。

### Q3：登录态采集怎么实现？
A：Playwright 注入 cookie，cookie 持久化到 JSON 文件。验证码用 ddddocr 识别，失败重试 ≤ 3 次。401 时自动重新登录。

### Q4：增量推送如何保证不重复？
A：两层保障。第一层 PushLog 表 `(subscription_id, tender_id)` 联合唯一约束；第二层 SQL NOT EXISTS 查询在数据库层面过滤已推送记录。

### Q5：反幻觉校验的原理？
A：正则提取 8 个关键字段（招标编号、预算、截止时间等），与采集原文做字段比对。如果报告中的字段在原文找不到，记为 warning；如果关键字段缺失，扣分。

### Q6：系统部署需要多少资源？
A：Docker 三容器部署，web + worker + scheduler + redis。最小配置 2GB 内存 + 1 核 CPU 即可运行。

### Q7：如何扩展到更多平台？
A：实现 `BaseTemplate` 接口，定义 `selectors / list_selector / wait_for_selector` 等字段，注册到 `app/templates/__init__.py` 即可。

### Q8：LLM 失败怎么办？
A：三级降级链路：DeepSeek API → 关键词正则兜底 → 默认空值。即使 LLM 完全不可用，系统仍能工作（用关键词正则解析）。
