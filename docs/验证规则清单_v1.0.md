# 招投标数据验证规则清单 v1.0

> **版本**：规则清单 v1.0（对应校验引擎 VALIDATOR_VERSION = 1.4）
> **性质**：纯确定性规则引擎，**零 LLM 依赖**，可 7×24 离线批量运行
> **生成日期**：2026-08-05
> **代码位置**：`app/processors/field_validator*.py`、`app/processors/evidence_locator/`、`app/eval/set_metrics.py`
> **对应规范**：Sol 规划 v4.1 第六章 6.2（确定性等价变换）、第七章 7.3（金额正确性判定）

---

## 0. 设计原则（工程约束）

| 编号 | 约束 | 说明 |
|------|------|------|
| G-01 | 原始值永不覆盖 | 所有校验结果保留 `raw_value`，规范化值另存 `normalized` |
| G-02 | 推导全程留痕 | 每次变换记录 `derivation_rule`（预处理步骤 + 换算公式） |
| G-03 | 规则版本化 | `VALIDATOR_VERSION` 常量随规则变更递增，评测结果必须绑定版本 |
| G-04 | 失败不抛异常 | 校验失败返回 `ValidationResult(valid=False, errors=[...])`，支持批量不中断 |
| G-05 | 零 LLM | 本清单全部规则为正则/确定性计算，不调用任何模型 |
| G-06 | 批量支持 | `validate_amount_batch` / `validate_date_batch` / `validate_identifier_batch` |

## 1. 金额校验规则（A 系列）

| 编号 | 规则 | 判定逻辑 | 示例 |
|------|------|----------|------|
| A-01 | 格式合法性 | `[币种前缀?] 数字(支持千分位) [单位?]`，不匹配即 invalid | `1,234.56`、`￥100`、`1.5亿` ✅；`约100万` ❌ |
| A-02 | 上下文前缀剥离 | 剥离"中标（成交）金额：人民币"类前缀后再匹配 | `中标金额：人民币100万元` → `100万元` |
| A-03 | 括号单位展开 | `数字（单位）` 结尾时，单位提出到数字后（必须先于后缀剥离） | `0.0769040（万元）` → `0.0769040万元` |
| A-04 | 后缀剥离 | 剥离尾部括号备注（人民币/含税等） | `100万元（含税）` → `100万元` |
| A-05 | 单位换算 | 万元×10⁴、亿元×10⁸，统一为"元" | `1.5亿元` → `150000000.0元` |
| A-06 | 规范化展示 | ≥1亿→亿元记法；≥1万→万元记法；否则元记法（均保留 2 位小数） | `1234567元` → `123.46万元` |
| A-07 | 金额类型枚举 | 仅允许 budget / ceiling / award / contract / unit_price；`unknown/其他/未指定` 容错为 None；其余值 invalid | `amount_type="unknown"` → None + 留痕 |
| A-08 | 币种一致性 | 识别 ￥/¥/人民币→CNY、$/美元→USD、€/欧元→EUR；缺省 CNY | `美元100万` → currency=USD |
| A-09 | 分包一致性 | Σ(分包金额) 与总金额差值 > 容差 → warning（不阻断） | 总和差 60 元 > 容差 50 元 → warning |
| A-10 | 零金额预警 | 金额=0 时 warning：可能流标或异常 | `0元` → valid 但带 warning |

## 2. 容差规则（T 系列，v4.1 §7.3 合规）

| 编号 | 规则 | 判定逻辑 | 示例 |
|------|------|----------|------|
| T-01 | 显示精度容差 | 最大允许误差 = 原文最小显示单位 ÷ 2 | `0.01万元` → 最小单位 100 元，容差 50 元 |
| T-02 | 精度缺失回退 | 按单位保守推断：万元→50 元、亿元→50 万元、元→0.005 元；外币（需汇率）→ None 不判定 | `original_unit="万元"` → 容差 50 元 |
| T-03 | 禁止项 | **明确禁止**固定百分比或金额量级分层容差；旧量级函数仅分包检查保留并标注 DEPRECATED | — |

## 3. 日期校验规则（D 系列）

| 编号 | 规则 | 判定逻辑 | 示例 |
|------|------|----------|------|
| D-01 | 三格式支持 | 中文（年月日 + 可选汉字/冒号时分）、ISO（YYYY-MM-DD）、点号（YYYY.MM.DD） | `2026年8月6日09时00分`、`2026.8.1 09:00` ✅ |
| D-02 | 括号备注剥离 | 循环剥离任意括号备注后再匹配 | `2026年8月10日（原8月1日）` → `2026年8月10日` |
| D-03 | 有效性校验 | 月份 1–12；日 ≤ 当月天数（2 月按 29 上限） | `2月30日` ❌ |
| D-04 | 规范化输出 | 统一 `YYYY-MM-DD [HH:MM]`，月日补零 | `2026年8月1日` → `2026-08-01` |

## 4. 编号校验规则（I 系列）

| 编号 | 规则 | 判定逻辑 | 示例 |
|------|------|----------|------|
| I-01 | 全角转半角 | 全角字符（FF01–FF5E）−0xFEE0，全角空格→半角 | `ＸＭＪＺ－０１` → `XMJZ-01` |
| I-02 | 多编号取首项 | 顿号/分号分隔时取第一个 | `A-010、B-06080` → `A-010` |
| I-03 | 括号备注剥离 | 剥离 `(2026)`、`(H)` 等括号片段（内容留存供回退） | `ZKQ2026-020514384ZF(H)` → `ZKQ2026-020514384ZF` |
| I-04 | 非法回退 | 主编号非法时，从被剥离括号内提取"招标/项目/采购/合同编号：XXX" | `(招标编号：0773-2641GNSHFWGK1900)` → `0773-2641GNSHFWGK1900` |
| I-05 | 规范化 | 去空格 + 统一转大写 | `xmjz-g-2026-010` → `XMJZ-G-2026-010` |
| I-06 | 格式约束 | 仅字母/数字/下划线/连字符，长度 ≥ 4，字母或数字开头 | `11000026210200173767-XM001` ✅ |

## 5. 证据定位验证（E 系列，evidence_locator）

| 编号 | 规则 | 判定逻辑 |
|------|------|----------|
| E-01 | 偏移边界 | `0 ≤ start < end ≤ len(raw_text)`，越界即 invalid |
| E-02 | 切片完全匹配 | `raw_text[start:end] == evidence_text` 为唯一真值基准 |
| E-03 | 尾部换行容差 | rstrip("\n") 后相等 → valid |
| E-04 | 首尾空白容差 | strip() 后相等 → valid |

## 6. 评测指标规则（M 系列，set_metrics）

| 编号 | 规则 | 说明 |
|------|------|------|
| M-01 | 全角/半角归一 | 比对前统一归一，防止字符宽度差异造成假阴性 |
| M-02 | 集合级 P/R/F1 | 多值字段按集合计算，不受顺序影响 |
| M-03 | null 误报率 | 预测为 null 但金标有值的比例，目标 < 5%（final5 实测 0.63%） |

## 7. 规则变更流程（强制）

1. 修改规则代码 → 2. `VALIDATOR_VERSION` 递增 → 3. 更新本清单对应条目并记录日期
→ 4. 补充回归用例（tests/test_field_validator*.py）→ 5. 全量测试通过 → 6. CHANGELOG 记录

## 9. 已知限制

- 外币（USD/EUR/JPY）容差因需汇率暂不判定（返回 None，不误判）
- 日期月份天数校验不考虑闰年精确性（2 月统一按 29 日上限）
- `_compute_tolerance`（量级分层）为不合规遗留策略，仅分包一致性检查保留，禁止新代码调用
